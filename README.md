# Kalman-Keltner Scanner

**A multi-timeframe swing-trade scanner built on a dual-speed Kalman filter pair with
ATR-graded pullback zones** — implemented twice: as TradeStation (EasyLanguage) RadarScreen
studies for live universe scanning, and as a parity-ported NumPy engine that powers the
screening backend of my options-screener project.

Personal project, designed and built solo. This is a **showcase repository** — the signal
parameters and full source are private, but I'm happy to walk through the implementation in
detail. See also [OptBridge](https://github.com/THEGRISC/OptBridge), my options portfolio
monitor.

## The idea

Moving averages force a bad trade-off: fast ones whipsaw, slow ones lag. Instead, the
scanner runs **two Kalman filters over the same daily bars** — identical recursive
structure, different noise tuning:

- a **fast filter** that tracks price closely and acts as the value centerline, and
- a **slow drift filter** that approximates a *weekly* bias without needing a second
  data series — one feed, two effective timeframes.

The drift filter feeds a **latching regime state machine** (fresh vs. sustained, bullish
vs. bearish) so the scanner only hunts long pullbacks while the higher-timeframe drift is
rising — and distinguishes a fresh turn from an established trend.

Wilder-ATR bands hung below the fast estimate define **graded pullback zones**: instead of
a binary "triggered / not triggered," every candidate gets a zone-depth score, so the
RadarScreen sort surfaces the *deepest statistically-defined value* first. Liquidity
filters (market cap, average volume) pre-screen the universe so only tradeable names load.

## Two implementations, one model

**TradeStation / EasyLanguage** — a RadarScreen indicator plus a Scanner universe-filter
expression: scan the full NASDAQ/NYSE universe, send survivors to RadarScreen, sort by
score. The daily workflow takes about a minute.

**Python / NumPy** — a line-for-line parity port of the EasyLanguage engine:

- The Kalman recursions are **path-dependent and deliberately kept sequential** — the port
  documents why they must not be naively vectorized, while the zone scoring layer *is*
  fully vectorized.
- ATR matches TradeStation's `AvgTrueRange` semantics exactly (simple-average seed,
  Wilder recursive smoothing), so both implementations agree bar-for-bar.
- **Warm-start support**: filter state persists and restores, so a long-running watchlist
  service can restart without re-warming hundreds of bars of history.
- Indexing differences between EasyLanguage's 1-indexed bars and Python are confined to
  the warmup period and documented — live output is identical.

In the options-screener project, this engine's weekly + daily **zone confluence** is
overlaid with an implied-vs-realized volatility ranking ("vol cone") to surface
trend-aligned options candidates whose implied vol is cheap relative to how the underlying
actually moves.

## Engineering discipline

- No look-ahead anywhere: latching states and sequential recursion only ever read the past.
- A minimum warmup-bar requirement is enforced before any signal is trusted — the slow
  filter needs history to converge.
- Both implementations verified against each other on identical bar data.
